# tupleboard

Пространство кортежей с арендами: **ассоциативная разделяемая память для агентов**, а не
очередь в топик. Производитель кладёт задачу, потребитель ищет её **по шаблону**; взятая
задача живёт под арендой, и если агент умер — задача возвращается сама.

Rust, одна зависимость (`serde`/`serde_json` — формат на проводе), HTTP на `std::net`.

```bash
cargo test          # 27 тестов
cargo run -- demo   # 18 проверок: падение агента, kill -9 сервера, backpressure
```

## Откуда это

Из архива музея потерянных идей, запись
[`linda`](https://kostyk348.github.io/lost-tech-museum/) — Linda (Йель, Дэвид Гелернтер, 1986),
JavaSpaces/Jini, `tuple space`:

> «Связь без адресов: производитель кладёт данные, потребитель ищет по шаблону; процессы
> развязаны по времени и по месту; leases автоматически убирают потерянные ресурсы» —
> формулировка записи архива.

> «Доска для агентов: долгоживущие LLM-агенты должны общаться через разделяемое пространство
> (поиск по шаблону + TTL/аренды), а не через прямые вызовы. Это лечит восстановление после
> сбоев, backpressure и "агент упал — задача не потерялась"» — питч записи.

Архив пишет, что идея умерла: JavaSpaces не выдержал конкуренции с брокерами и базами, Apache
River закрыли в 2022-м из-за отсутствия активности. Здесь она переизобретена там, где брокер
действительно лишний: маленькая очередь работы с восстановлением после падений.

## Быстрый старт

```bash
cargo run --release -- serve --store data/space.json --port 8801 --lease 30 &

# положить задачу
cargo run -- put '["translate","doc-1"]'

# взять по шаблону: любая задача перевода, под арендой 30 секунд
cargo run -- take '["translate","?doc"]' --lease 30 --owner worker-1
# receipt: r-… (аренда 30s; подтвердить: ack, вернуть: nack)

# подтвердить — с доказательством
cargo run -- ack r-… --evidence "перевод готов: /tmp/doc-1.ru.pdf"

cargo run -- stats
```

Что печатает демонстрация (сокращённо, реальный вывод):

```
3. worker-A взял задачу под арендой и умер: ack не приходит, сервера больше нет
  ✓ сервер убит сигналом
  ✓ задачи пережили падение сервера
  ✓ задача worker-A ещё в работе — аренда жива
4. аренда истекает сама — задача возвращается в пространство
  ✓ ту же задачу взял другой агент
  ✓ видно, что это вторая попытка
6. backpressure: полное пространство отказывает честно
  ✓ лишняя задача отклонена 429

итог: проверок 18, провалено 0 — работает
```

## Шаблоны

Шаблон — JSON-массив той же длины, что и поля:

| поле шаблона | смысл |
|---|---|
| `"translate"`, `1`, `true`, `null`, `[1,2]` | точное совпадение (тип учитывается: `true` ≠ `1`) |
| `"*"` | любое значение |
| `"?doc"` | любое значение, связать с именем `doc`; одно имя — одно значение |

Литеральный `"*"` или `"?x"` как данные неотличим от шаблона — это осознанное ограничение
синтаксиса, а не баг.

## HTTP-API

| метод | путь | что делает |
|---|---|---|
| `POST` | `/out` | `{"fields": [...], "ttl": 600}` → `201`; мест нет → `429` |
| `POST` | `/rd` | `{"pattern": [...], "timeout": 3}` → `200` или `404` |
| `POST` | `/in` | `{"pattern": [...], "timeout", "lease", "owner"}` → `200` с `receipt` или `404` |
| `POST` | `/ack` | `{"receipt", "evidence"}` → `200`; без доказательства при `--require-evidence` → `422` |
| `POST` | `/nack` | `{"receipt"}` → `200`: вернуть сразу, не дожидаясь аренды |
| `POST` | `/extend` | `{"receipt", "seconds"}` → `200` |
| `GET` | `/stats` | что в пространстве, что в работе, счётчики |
| `GET` | `/tuples` | полный дамп |
| `GET` | `/healthz` | `{"ok": true, …}` |

Коды — контракт, а не пожелание: `400` кривой шаблон, `404` нет совпадений или аренды,
`422` нет доказательства, `429` мест нет (`Retry-After`).

## Три механизма, ради которых это написано

1. **Аренда.** Взял задачу — получил `receipt` и срок. Не подтвердил (упал) — срок истёк,
   задача вернулась в хвост пространства и досталась следующему; счётчик попыток растёт.
   `nack` возвращает сразу, `extend` продлевает.
2. **Гейт доказательства.** `ack` без `evidence` при `--require-evidence` — отказ `422`.
   «Сделано» — это артефакт (вывод команды, URL, лог), а не заявление.
3. **Ёмкость.** Полное пространство отвечает `429` с причиной вместо бесконечного роста.

## Где это НЕ нужно (важно)

**Наш собственный канбан это уже умеет.** У `hermes kanban` есть `claim` (атомарный захват),
`reclaim`, `heartbeat`, `runs` и `diagnostics` с проверкой `stranded_in_ready`. Строить второй
координатор рядом — не улучшение, а рассинхрон двух источников правды.

Где смысл есть: очереди работы **внутри** приложений, которым канбан не нужен — например
пайплайн документов: воркер взял документ, упал, документ вернулся. Плюс это работающий
экспонат идеи, которая в архиве была только питчем.

Организационная часть (как из этого сделать архитектуру команды: VSM Бира, закон необходимого
разнообразия Эшби, POSIWID) — в [`docs/TEAM-CYBERNETICS.md`](docs/TEAM-CYBERNETICS.md).

## Ограничения (честный список)

* снимок всего состояния на каждое изменение — O(n) на запись; для тысяч задач нужен журнал,
  а не снимок;
* один процесс на файл состояния: два сервера на одном `--store` затрут друг друга;
* нет TLS и аутентификации: `POST /out` открыт всем, кто дотянулся до порта;
* нет атомарности между кортежами (транзакций «всё или ничего» нет — это не база);
* нет подписки на изменения (notify/watch) — это работа другого экспоната, `hubd`;
* шаблон не поддерживает отрицание и сравнения (`> 5`, `!= x`) — только равенство, `*` и связки;
* доказательство не проверяется на подлинность: `evidence` — строка. Проверяет аудит, а не сервис.
